# 外置候场队列与游戏场景一致性设计

## 目标

让手机场景容器只展示游戏开局时应存在的 HUD、棋盘和背景；未掉落的候场切片移到手机容器上方，同时保留与棋盘列一一对应的掉落关系。

## 范围与约束

- 不修改关卡数据、队列顺序、切片资源或交换逻辑。
- 手机容器内部不显示任何候场切片或候场列标签。
- 外置候场区放在手机容器正上方，候场列中心与手机内棋盘列中心严格对齐。
- 编辑器候场区的切片完全展开，最下方是下一张掉落切片。
- 运行预览采用同一外置结构，但候场切片保留重叠堆叠效果。
- 4×4、5×5、6×6 和最长候场列均须不遮挡手机框、HUD、棋盘或画布控制项。
- 手机内的 HUD、背景和棋盘尺寸由游戏场景可用区域决定，不再被候场区压缩。

## 方案

每个手机预览包裹在一个“场景组合容器”中。组合容器从上到下由外置候场区和手机容器组成：候场区本身不属于手机背景；手机内部仅包含 HUD 和棋盘。两者共用同一个棋盘宽度 CSS 变量，以保证每个候场列准确指向对应棋盘列。

布局计算拆成两个尺寸约束：手机内依据棋盘规格和切片比例计算棋盘，保持游戏场景稳定；手机外依据最长候场列计算候场区高度。组合容器按两者总高度居中放置在编辑器画布或运行预览舞台中。长队列只缩放外置候场区和整体组合，不会挤压手机内的游戏画面。

## 模块边界

- `editor-state.mjs`：布局函数接受棋盘和候场的独立可用空间，返回手机内棋盘尺寸、候场高度与组合总高度；保持无 DOM 依赖。
- `app.mjs`：将外置候场区和手机容器分别赋予布局变量；每次切换关卡或交换切片后重新计算。
- `index.html`：增加编辑器和运行预览各自的组合容器，使候场区成为手机容器的相邻元素而非子元素。
- `styles.css`：以组合容器为定位基准；候场区在上、手机在下；删除手机内候场区的绝对定位规则。
- `editor-state.test.mjs`：验证棋盘尺寸不随候场列长度变化，且候场与棋盘使用同一列宽。

## 错误处理

缺失切片尺寸、棋盘规格或队列数据时，沿用安全默认值，生成有限的棋盘和候场尺寸。既有关卡加载错误提示保持不变。

## 验证

1. 先新增失败测试：相同棋盘、不同候场长度时，手机内棋盘尺寸相同；外置候场区仍可容纳完整队列。
2. 检查代表关卡 1、15、21、24、27、30：手机内无候场切片，候场在手机正上方，列与棋盘对齐。
3. 检查运行预览：候场仍在手机上方且重叠显示，手机内游戏场景没有候场元素。
4. 运行完整 Node 测试，并确认浏览器控制台无错误。
