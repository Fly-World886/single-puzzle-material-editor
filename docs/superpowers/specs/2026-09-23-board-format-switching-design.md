# 棋盘规格切换设计

## 目标

在右侧“棋盘”工作区让编辑者把当前关卡的正方形棋盘切换为 4×4、5×5 或 6×6。切换不得改变图片、图片切分规格或任一切片的身份；编辑器场景、静态运行预览和已启动的 WebGL 试玩必须立即使用新布局。

## 范围与约束

- 仅支持 4×4、5×5、6×6 三种正方形棋盘；不提供自定义长宽或矩形棋盘。
- `layout.matchSize` 保持原值，现有关卡的 2×2 图片切片不重切、不重新生成。
- 一次切换保留 `layout.pictures` 及所有 `{ pictureIndex, tileIndex }` 条目各一次；不新增、删除、修改图片或切片。
- 目标棋盘的格数大于当前全部切片数时，拒绝切换，保持当前布局不变。
- 切换仅更新当前内存中的编辑布局，沿用现有草稿保存、校验和导出入口；本次不扩展持久化或撤销功能。
- 当前项目的预览模型以 `boardSize.width` 为网格边长；切换时必须把 `boardSize.width` 和 `boardSize.height` 同步设为相同目标值。

## 用户交互

“棋盘”工作区在“拼图规格”信息下增加“棋盘格式”区块：

- `<select>` 仅列出 `4 × 4`、`5 × 5`、`6 × 6`，加载关卡和切换关卡时自动反映当前规格。
- “应用格式”按钮仅在选择值不同于当前规格时可点击。
- 区块说明会注明“会重新分配全部切片到目标列；图片和切片不会删除”。
- 点击按钮后使用浏览器确认框，明确显示旧规格和新规格；取消不会修改数据。
- 成功后更新场景、静态预览、棋盘信息、完整性摘要与 WebGL 试玩数据，并在画布提示本次规格和重排完成。
- 如果目标棋盘格数超过切片总数，按钮操作显示“切片不足，无法填满 N×N 开局棋盘”，不调用渲染或试玩同步。

## 数据与重排规则

新增无 DOM 依赖的 `changeBoardFormat(layout, targetSize)`，放在 `editor-state.mjs`。

输入有效时按以下固定算法产生全新布局对象：

1. 读取源队列，按“源列从左至右、每列 `tiles` 数组从索引 0 到末尾”的顺序扁平化所有切片。这与当前模型的列内落子顺序一致，因而同一来源每列内部顺序不会反转。
2. 验证扁平后切片总数不少于 `targetSize * targetSize`；不足时返回原 `layout` 及 `changed: false, reason: 'insufficient-tiles'`。
3. 创建正好 `targetSize` 个 `{ tiles: [] }` 队列，并按扁平数组顺序循环分配：第 `index` 个切片进入 `queues[index % targetSize]`。这样每列长度最多相差一，列内顺序稳定，且所有切片都保留。
4. 返回 `boardSize: { width: targetSize, height: targetSize }` 和新队列，保留布局的其他字段与图片对象引用。

`createLevelPreview()` 已将每列前 `gridSize` 张视为开局棋盘、余项视为候场。因此无需另存棋盘数组：重排后的每个新队列前 N 张自然构成 N×N 开局，其他条目自动进入候场区。

目标值不在 `4, 5, 6`、源布局没有数组队列、目标等于现有正方形规格时，函数返回原布局和 `changed: false`，并以 `invalid-target`、`invalid-layout` 或 `unchanged` 说明原因。函数不得修改传入布局或其中的队列数组。

## 模块边界

- `index.html`：在 `data-workspace="board"` 的棋盘信息区声明格式标签、选择器、说明文字和应用按钮。
- `styles.css`：为该区块提供紧凑的纵向布局、提示文本和禁用按钮样式，沿用右侧检查器的颜色与间距。
- `editor-state.mjs`：导出 `changeBoardFormat(layout, targetSize)`；负责输入验证、不可变重排和结果状态，不读取 DOM。
- `app.mjs`：取得新控件，随当前布局同步显示选择值和按钮状态；确认后调用状态函数，清空图片/场景切片选择，重建 `activePreview`，刷新全部关联视图并发布 WebGL 数据。
- `editor-state.test.mjs`：覆盖重排纯函数与拒绝条件；不依赖浏览器 DOM。

## 错误处理

格式选择器永远只给出支持的规格，但状态函数仍会防御性校验外部调用。异常或无效布局不应破坏现有场景；调用方保留当前 `activeLayout`，以画布提示说明失败原因。切换后的完整性摘要继续使用既有切片数量、索引、重复性与队列列数检查。

## 验证

1. 添加 4→5、5→6、6→4 的失败测试：断言 `boardSize` 的宽高同步、队列数等于目标边长、切片扁平总数和每个切片身份集合均不变、最大与最小队列长度差不超过 1、原布局未被修改。
2. 添加相同规格、非法目标、缺失队列、切片少于目标格数的测试，断言返回原布局、`changed: false` 和正确原因。
3. 实现状态函数后运行 `node --test editor-state.test.mjs editor-launcher.test.mjs webgl-preview-bridge.test.mjs`。
4. 在浏览器分别加载 4×4、5×5、6×6 关卡，依次切换到其余两种规格；确认编辑器候场队列、静态预览和 WebGL 试玩同步，且校验摘要通过。

## 设计自检

- 覆盖范围：UI、确认交互、不可变数据迁移、三种预览、失败提示和自动化/手动验证均已定义。
- 一致性：格式切换只写入正方形 `boardSize`；`matchSize`、图片和切片保持不变，符合限定范围。
- 边界：目标开局无法填满时明确拒绝；无效输入与相同规格均不产生副作用。
