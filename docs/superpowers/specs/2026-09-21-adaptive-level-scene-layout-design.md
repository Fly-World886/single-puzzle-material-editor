# 关卡场景自适应布局设计

## 目标

让关卡场景和运行预览依据关卡棋盘尺寸、切片比例与各列候场切片数量自动缩放，使 4×4、5×5、6×6 关卡均完整显示在各自手机画布内。

## 范围与约束

- 不修改任何关卡数据、切片顺序或游戏规则。
- 编辑器场景的候场切片保持完全展开；每列下一张掉落切片在最下方、紧贴棋盘。
- 运行预览的候场切片继续使用游戏式重叠堆叠；顺序与编辑器场景一致。
- 棋盘列与候场列保持水平对齐。
- 布局不得突破手机画布边框；4×4、5×5、6×6 和最长约 11 张的列队列必须可见。
- 现有图片交换、HUD、运行状态与关卡完整性校验不改变。

## 方案

新增一个无 DOM 依赖的布局计算函数，输入棋盘边长、切片宽高、各列候场数以及手机内容区尺寸，输出棋盘宽度、切片宽度、队列间距、候场区高度和内容总高度。

布局从可用宽度推导最大棋盘宽度，再从“候场区高度 + 间距 + 棋盘高度”推导可容纳该关卡的切片宽度。编辑器候场区采用完全展开的切片高度；运行预览采用重叠后的堆叠高度。计算结果限制在最小可读尺寸和内容区上限之间，保证任何布局不会从画布顶部或底部溢出。

`app.mjs` 在每次渲染关卡时分别计算编辑器场景和运行预览的结果，并把结果写为 CSS 自定义属性。CSS 只负责用这些变量布置棋盘、列队列与间距，移除固定的棋盘和候场尺寸假设。

## 模块边界

- `editor-state.mjs`：导出 `calculateSceneLayout(input)`；不读取 DOM，不直接修改样式。
- `app.mjs`：从 `createLevelPreview()` 获得各列候场数，调用布局计算，并将结果设置到场景容器的 CSS 变量。
- `styles.css`：用 `--board-width`、`--queue-tile-width`、`--queue-gap` 等变量渲染布局；保留编辑器展开与运行预览重叠的不同视觉规则。
- `editor-state.test.mjs`：覆盖不同棋盘规格、切片比例与长队列，断言输出不会超过给定内容区，且列宽与棋盘网格对应。

## 错误处理

无效或缺失的布局参数使用安全下限（最小棋盘边长、最小切片尺寸、空队列），仍返回有限且非负的布局值。关卡加载失败时沿用既有的错误提示与清空逻辑。

## 验证

1. 先添加失败的纯函数测试，覆盖 4×4、5×5、6×6 与长候场队列。
2. 实现计算函数后运行全部 Node 测试。
3. 在浏览器逐项检查关卡 1、15、21、24、27、30：场景候场完全展开、运行预览仍重叠、棋盘列对齐且无纵向溢出。
